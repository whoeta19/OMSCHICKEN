## 1. Сравнение дат DD.MM.YYYY как строк (класс критичных багов)

Функция `parseDMY()` есть только в 3 файлах (index.html, analytics.html, counterparty.html) — локальными копиями, не общая.

**Найденные нарушения:**

| Файл:строка | Код | Проблема |
|---|---|---|
| `docs.html:1741` | `b.date.localeCompare(a.date)` | Сортировка документов «по дате» строками — неверный порядок при пересечении месяца/года |
| `docs.html:1742` | `a.date.localeCompare(b.date)` | То же, обратная сортировка |

**Корректные места (для справки, не трогать):** index.html:3002/3102/3697 (parseDMY/parseDMYtoDate), counterparty.html:647, сортировка `byMonth` в index.html:3694 сравнивает ключи `MM.YYYY` через localeCompare — **тоже баг**: `'12.2025' < '01.2026'` даст неверный порядок (сортирует по месяцу, игнорируя год).

**Итого к исправлению:** docs.html (2 места), index.html:3694 (ключи MM.YYYY).
**Системное решение:** единый `js/utils.js` c `parseDMY()`, `formatDMY()`, `parsePeriod()` — подключить на все страницы, удалить 3 локальные копии.

## 2. Молчаливое проглатывание ошибок (`catch(e) {}`)

Всего **43 пустых catch** по проекту:

| Файл | Кол-во | Критичность |
|---|---|---|
| index.html | 15 | Высокая — среди них загрузка компаний/транзакций: пользователь видит вечный skeleton без сообщения |
| counterparty.html | 5 | Средняя — проверка контрагента молча «не работает» |
| settings.html | 4 | Средняя |
| api/transactions.js | 4 | Средняя — на сервере теряется причина 500 |
| api/lookup.js | 3 | Средняя |
| js/auth.js, api/notify.js | по 2 | Низкая (фоновые уведомления — допустимо) |
| analytics, declarations, docs, onboarding, vat, warehouse, api/companies, api/company_settings | по 1 | Разная |

**Решение:** каждый catch в пользовательском потоке → `showToast('❌ ...')` + `console.error(e)`. Фоновые (телеграм-нотификации, audit log) можно оставить, но добавить `console.error`.

## 3. Дублирующийся код между страницами

- **Форматирование денег:** 10+ локальных копий `fmt()` / `fmtMoney()` / `fmt2()` / `fmtShort()` с разными правилами округления (где-то 0 знаков, где-то 2, где-то `Math.abs`!). Файлы: companies-overview, docs (2 шт.), index, marketplace, negotiation, payroll, tools, warehouse, analytics.
- **Даты:** 3 копии parseDMY + локальные fmtNextDate и др.
- **Шапка/сайдбар:** повторяется в 10+ страницах вручную — при добавлении нового пункта меню надо править все файлы (уже сейчас есть расхождения в наборе пунктов).
- **Тосты:** `showToast` скопирован в 12 страниц с чуть разной вёрсткой/таймингом.
- **CSS:** `:root{--bg...}` палитра скопирована в каждый файл, значения местами разошлись.

**Решение (Фаза 3):** `js/utils.js` (деньги/даты/тосты), `styles/design-system.css`, шапку — генерировать одним js (`js/nav.js`).

## 5. Формы без валидации и disabled-состояния

- `<form>`/`onsubmit` не используется нигде — все «формы» это div+onclick, т.е. нет нативной валидации, Enter не отправляет.
- disabled при отправке есть только в login.html и 1 кнопке settings.html (Telegram). Нет в: payroll (создание сотрудника/начисления), docs (генерация), settings (остальные кнопки), index (добавление операции), warehouse, marketplace. Двойной клик = дубли записей (у транзакций спасает hash, у сотрудников/начислений — нет).
- Числовые поля почти нигде не проверяются на NaN/отрицательные до отправки (сервер проверяет только транзакции — validateTx).

## 6. Захардкоженный НДС 10% (для будущего мультиставочного 10/22%)

- **vat.html:** строки 188, 192, 203, 207, 484 (тексты и заголовки таблиц «НДС 10%»); селекты ставок есть (228, 258 — 10/22 выбираемо в калькуляторе), но основной расчёт по выписке — жёстко 10% (`/1.1`).
- **declarations.html:** 244, 370, 380, 393, 780, 789, 945–954 — декларация НДС считает продажи из выписки только по 10%, 22% вводится вручную.
- **tools.html:** калькулятор НДС — ставка выбираемая, ок.
- **index.html:** карточка «НДС к уплате» на дашборде — жёстко 10%.

**Решение (не в этой итерации):** ставка per-категория/транзакция в БД + настройка компании «основная ставка НДС».

## 7. Несоответствия вёрстки

- **Радиусы:** используются 6/8/10/12/14/16/20px вперемешку, часто в одном файле (index: 6,8,10,12,14,20). Нужна шкала 8/12/16.
- **Шрифты:** 4 семейства — Unbounded (заголовки), Inter, **Nunito** (20 вхождений — легаси, выбивается), Arial/Times (в печатных формах документов — там оправдано). Написание вразнобой: `'Inter',sans-serif` и `Inter,sans-serif`.
- **Палитра:** `:root` скопирован в каждый файл; есть остатки темы `body.aurora` (фиолетовая, rgba(167,139,250,...)) в vat/declarations/tools — мёртвый код от старой светлой/aurora темы.
- **Отступы:** magic numbers повсюду, spacing-шкалы нет.
