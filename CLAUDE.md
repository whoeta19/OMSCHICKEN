# OMSFIN — контекст проекта

## Что это
OMSFIN — облачный финансовый/бухгалтерский сервис для малого и среднего бизнеса в РФ.
Изначально строился на кейсе ООО «ОМСЧИКЕН» (оптовая торговля мясом птицы), но продукт
позиционируется на широкий рынок предпринимателей — конкурент Моё Дело / Эльба / СБИС
для сегмента малого бизнеса.

## Стек
- Фронтенд: чистый HTML/CSS/JS (без фреймворков), отдельная страница на каждый раздел
- Бэкенд: Vercel Serverless Functions (Node.js, ESM, `export default async function handler(req, res)`)
- БД: Supabase (Postgres + Auth + REST API через PostgREST)
- Деплой: Vercel, репозиторий на GitHub — `whoeta19/OMSCHICKEN`
- Telegram-бот `@omsfin_bot` для уведомлений

## КРИТИЧНО: лимит serverless-функций
**Vercel Hobby (бесплатный тариф) разрешает максимум 12 serverless-функций на деплой.**
Каждый `.js`-файл в папке `api/` = отдельная функция. Сейчас используется ~11 файлов.
**Перед добавлением НОВОГО файла в `api/` — сначала проверь, нельзя ли добавить
ресурс/действие в УЖЕ существующий файл через query-параметр** (`?resource=...`,
`?action=...`, `?provider=...`) — именно так уже объединены несколько функций:
- `api/members.js` — обслуживает и команду (участники/роли/приглашения), и audit log
  (через `?resource=audit-log`)
- `api/lookup.js` — обслуживает и Dadata, и ЕГРЮЛ (через `?provider=dadata|egrul`)
- `api/employees.js` — обслуживает и сотрудников, и зарплатные начисления
  (через `?resource=employees|payroll`)

Если превысить лимит 12 — Vercel **тихо проваливает сборку с Error**, но домен
продолжает показывать предыдущий успешный деплой, поэтому со стороны кажется,
что "код не обновился", хотя на самом деле сборка просто упала. Если деплой не
применяется — ПЕРВЫМ делом проверяй `vercel.com → Deployments → статус последнего
деплоя`, не количество файлов в commit.

## Архитектура данных (Supabase)
- `transactions` — банковские операции; ключевые поля: `date` (формат DD.MM.YYYY!),
  `amount`, `category`, `period` (формат MM.YYYY), `company_id`, `user_id`, `hash`
  (для дедупликации повторной/частичной загрузки выписки), `inn` (ИНН контрагента)
- `companies` — компании пользователя
- `company_members` — участники компании с ролями: `director` (всё),
  `accountant` (операции/декларации/НДС/документы, без настроек), `employee`
  (только документы, без финансов)
- `invite_codes` — коды приглашения в команду (срок 7 дней)
- `audit_log` — журнал действий (кто/что/когда), виден только директору
- `employees` / `payroll_runs` — сотрудники и история начислений зарплаты

## ВАЖНО: формат дат
Транзакции хранят дату как строку `DD.MM.YYYY` (день первым!).
**НИКОГДА не сравнивай эти даты через `>` `<` или `.localeCompare()` напрямую** —
это сравнение строк даёт неверный результат при пересечении границы месяца/года
(например `'20.12.2025' > '05.01.2026'` ошибочно даёт `true`). Всегда сначала
парсить через функцию вида:
```js
function parseDMY(str) {
  const [dd, mm, yyyy] = str.split('.').map(Number);
  return new Date(yyyy, mm - 1, dd).getTime();
}
```
Эта ошибка уже была найдена и исправлена в нескольких местах (analytics.html,
counterparty.html, финансовый радар в index.html) — не повторяй её в новом коде.

## Налоговые ставки 2026 (актуальные на момент создания проекта)
- НДС: 10% для базовых продуктов (мясо птицы без деликатесов и т.п.), 22% — новая
  базовая ставка (была 20%). Деликатесные позиции (копчёности, балык, окорочка-пастрома)
  облагаются 22%, даже если основной товар на 10%.
- НДФЛ (зарплата): прогрессивная шкала — 13% до 2.4 млн ₽/год, 15% до 5 млн,
  18% до 20 млн, 20% до 50 млн, 22% свыше. Считается нарастающим итогом с начала года.
- НДФЛ (дивиденды): отдельная, своя шкала — 13% до 2.4 млн ₽/год, 15% свыше.
  НЕ складывается с зарплатной базой — это разные налоговые базы.
- Налог на прибыль: 25% (8% федеральный + 17% региональный), было 20%.
- Страховые взносы: единый тариф 30% до предельной базы 2 979 000 ₽/год на сотрудника,
  15.1% сверх базы. Льготы МСП отменены с 2026. IT-аккредитованные компании — отдельный
  льготный тариф 15% / 7.6% сверх базы (повышен с 7.6% единого).
- УПД и счёт-фактура: с 01.04.2026 обязательна строка 5б (реквизиты авансового
  счёта-фактуры), если отгрузка идёт в счёт предоплаты.

Все эти ставки уже зашиты в код правильно (declarations.html, tools.html, employees.js) —
если меняешь расчёты, не возвращай старые цифры (20% НДС-база, плоский НДФЛ 13%,
налог на прибыль 20%, старые тарифы МСП по взносам).

## Известные упрощения (не баги, но стоит знать)
- НДС хардкожен на 10% по всему коду — корректно для ОМСЧИКЕН (только сырое мясо,
  без деликатесов), но НЕ универсально для всех будущих пользователей с другим
  ассортиментом. При расширении на другие отрасли нужно сделать ставку настраиваемой
  per-транзакция/категория.
- Налог на прибыль считается по кассовому методу (банковские списания), не по
  полному бухгалтерскому учёту — может не совпадать при наличии амортизации и т.п.

## Стиль кода
- Везде на русском — комментарии, сообщения об ошибках, тексты интерфейса
- CSS-переменные через `:root{--bg:...;--accent:#ff6b00;...}` — единая палитра
  во всех файлах, фирменный акцентный цвет — оранжевый `#ff6b00`. Сейчас тёмная тема
  (`--bg:#080808`), пробовали светлую — пользователю не понравилось, откатили обратно.
- Все API-функции проверяют роль через `company_members` перед изменением данных
- Токены/секреты (Dadata, Telegram bot token, Supabase service key) — хранятся
  в коде серверных функций (не идеально, но так сделано); внешние API-ключи
  (Dadata) переданы через переменные окружения Vercel

## ЖЕЛЕЗНЫЕ ПРАВИЛА (анти-баг система — обязательны для любой сессии)

1. **Даты** — только через `parseDMY()` / `toDMY()` / `parsePeriod()` из `/utils.js`.
   Никогда не сравнивать строки `DD.MM.YYYY` или `MM.YYYY` через `>`, `<`,
   `localeCompare` или голый `.sort()`.
2. **Деньги** — расчёты только в копейках через функции `/js/calc.js` (OMSCALC).
   Форматирование только `fmtMoney()` / `fmtMoney2()` из `/utils.js`.
   Никакой float-арифметики с рублями в страницах.
3. **Сетевые запросы** — через `safeFetch()` из `/utils.js` (таймаут, `.ok`,
   человеческие ошибки). Прямой `fetch` допустим только в перехватчиках
   auth и там, где нужен доступ к статусу ответа (с обязательным `.ok`
   и `r.json().catch(...)`).
4. **Расчётная логика** — новые формулы ТОЛЬКО в `/js/calc.js`, и в том же
   коммите — тест в `/tests/run.js`. Коммит расчёта без теста запрещён.
5. **Тесты и smoke**: перед коммитом `node tests/run.js` (pre-commit хук
   делает это сам — установка: `cp scripts/pre-commit.sh .git/hooks/pre-commit
   && chmod +x .git/hooks/pre-commit`). После деплоя — `sh scripts/smoke.sh`
   (проверяет все страницы и API прода).
6. **Пользовательские данные в DOM** — только `textContent` или
   `escapeHtml()` из `/utils.js`. `innerHTML` с `${...}` от пользователя /
   сервера — запрещён.
7. **Налоговые дедлайны** — время только `mskNow()` (Москва), не `new Date()`.
8. **Тосты, не alert()**. Успех операции показывать только ПОСЛЕ ответа
   сервера; кнопки отправки — `disabled` на время запроса.
