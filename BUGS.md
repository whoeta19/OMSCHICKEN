## КРИТИЧНО

### B1. Ручное добавление операции всегда падает на сервере
- **index.html:2528** — `addManual()` берёт дату из `<input type="date">` как есть: браузер отдаёт `YYYY-MM-DD`, а сервер (`api/transactions.js:86`) требует строго `DD.MM.YYYY` → любая ручная операция с датой получает 400 «date должен быть DD.MM.YYYY».
- Плюс не проставляется `period` (MM.YYYY) — операция не попадёт в фильтры периодов, даже если пройдёт.
- **Воспроизвести:** Дашборд → «+ Добавить» → заполнить → Сохранить. В консоли apiPost error 400.

### B2. «✅ Сохранено» показывается ДО ответа сервера
- **index.html:2538–2539** — `apiPost(...).then(...)` асинхронный, а тост успеха и очистка формы выполняются сразу. При ошибке сети/валидации пользователь видит «Сохранено», данные потеряны (поля уже очищены).
- **Воспроизвести:** выключить сеть → добавить операцию → «Сохранено», операции нет.

## СРЕДНЕ

### B3. XSS через ФИО сотрудника
- **payroll.html:203** — `${e.full_name}` вставляется в innerHTML без экранирования. Бухгалтер, добавивший сотрудника с именем `<img src=x onerror=...>`, выполнит JS у всех участников компании. Аналогично `${data.error}` (строки 190, 356) — текст ошибки сервера в innerHTML.
- **index.html:2539** — `${name}` контрагента в `addResult` без escapeHtml (self-XSS + сохранённое имя рендерится в списках).

### B4. Деньги во float по всему коду
- Все налоговые расчёты — float-арифметика в рублях: `tools.html:774–782` (НДФЛ дивиденды, взносы), `declarations.html:1104–1105, 1316–1318` (взносы 30/15.1), `vat.html:632–633` (НДС 10/110), `index.html:4677` (НДС на дашборде). Классика `0.1+0.2=0.30000000000000004` → расхождение на копейки между страницами и с декларацией.
- **Лечение (Контур 3):** единые money-функции в core.js (копейки/явное округление в одном месте), расчёты — в calc.js с тестами. Не чинить точечно по 30 местам.

### B5. fetch без response.ok / обработки
- **login.html** — 5 fetch, 0 проверок статуса (вход/регистрация читают body вслепую; работает, пока Supabase возвращает JSON, упадёт молча на 5xx/HTML-ответе).
- **onboarding.html** — 2 fetch без .ok (сохранение реквизитов, lookup).
- **js/auth.js:24** — refresh-fetch без .ok (компенсируется проверкой data.access_token — приемлемо, но при 5xx с HTML упадёт на .json()).
- **Лечение (Контур 3):** safeFetch в core.js + точечная замена.

### B6. Дедлайны налогов считаются по локальному времени пользователя
- **declarations.html:673, calendar.html:433, index.html (виджет календаря)** — `new Date()` в поясе пользователя. Для Владивостока (+7 к МСК) «до дедлайна 0 дней» наступит на 7 часов раньше реального МСК-дедлайна; в обратную сторону (Калининград) — на час позже. Для налоговых сроков корректно считать по Europe/Moscow.

### B7. Форма добавления сотрудника: нет валидации оклада на разумность, зато есть анти-дабл-клик (ок). Форма операции — есть валидация, нет disabled на время запроса (см. B2).
